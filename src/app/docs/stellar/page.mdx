# Stellar

Stellar is the planned settlement network for Feyo. Its low-cost, fast transactions and stablecoin ecosystem make it a strong fit for payment infrastructure, while the application still needs careful handling of authorization, assets, fees, and network configuration.

## Planned transaction lifecycle

Feyo will model a payment from intent to verification:

- identify the asset, issuer, network, and destination;
- validate the authorized amount and recipient;
- construct and sign through an explicitly controlled wallet boundary;
- submit the transaction to Stellar infrastructure;
- verify the resulting transaction and expose its status.

## Current status

The repository integrates Freighter wallet connection on Stellar Testnet for the `/app` workspace without initiating payments or transactions. No private keys are stored or managed by the application; only the public account address (`G...`) is queried.

## Freighter setup and testnet smoke test

To test the wallet connection locally with Freighter:

1. **Install Freighter**: Download the browser extension from [Freighter](https://www.freighter.app/).
2. **Switch to Testnet**: Open Freighter settings -> **Network**, and ensure **Test Net** is selected (`Test SDF Network ; September 2015`).
3. **Fund Test Account**: Generate or fund a test account using [Stellar Friendbot](https://laboratory.stellar.org/#account-creator?network=test). Testnet lumens have no real monetary value.
4. **Connect in `/app`**: Navigate to `/app` in your browser and select **Connect Freighter**. Approve the connection request in the Freighter dialog.
5. **Verify Safety Boundaries**: Test connecting with Freighter switched to Mainnet to verify that an unsupported network error is raised safely. Test declining authorization to verify error recovery. Disconnecting resets local session state without falsely claiming wallet permissions were revoked.

## Safety notes

Network, asset issuer, destination, and amount must be treated as security-sensitive inputs. Any future integration needs test coverage for malformed addresses, wrong-network assets, authorization scope, duplicate requests, and failed or pending transactions.
