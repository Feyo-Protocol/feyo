# Roadmap

Feyo is an independent open-source Stellar payments project. We are building it for long-term ecosystem usefulness, not a single event. The phases below describe our **direction**, not guaranteed dates or deployed features.

Our priority is straightforward: **correct payments, explicit authorization, independent verification, and a good developer experience.** Work is delivered through focused GitHub issues and reviewed pull requests.

## What is in the deployed foundation

- Responsive landing page, MDX developer documentation and search.
- Varial/Freighter public-wallet connection restricted to Stellar Testnet.
- Read-only XLM and issued-asset balances, preserving the issuer.
- Exact-decimal validated local drafts and truthful payment status UI.
- Deployed read-only Testnet transaction verification against an expected source, destination, exact amount and asset identity.
- Automated unit, documentation, CI and browser accessibility checks.

The current workspace does **not** sign, broadcast, or settle a payment. It has no Mainnet payments, public payment API, MCP payment execution, or bank payouts.

## Deployed — user-facing read-only verification

PR #31 completed Issue #28 and deployed a read-only transaction-hash interface against exact expected Testnet payment evidence, with bounded requests, cancellation and accessible outcome states. Production checks on November 22, 2026 confirmed the exact-match, amount-mismatch and invalid-hash paths using an unrelated public Testnet transaction. Feyo did not create, fund, sign or submit that transaction, and the workspace still cannot execute payments.

## Next: trustworthy Testnet payment preparation

- Better session-only draft management.
- Recipient readiness and issued-asset trustline checks.
- Browser, accessibility and real-wallet regression coverage.

## Then: explicitly authorized Testnet transactions

1. Preview a bounded unsigned classic Stellar payment with amount, asset, issuer, destination, fee, timeout and network shown.
2. Ask the connected wallet for explicit user authorization and a signature; signing alone is not submission.
3. Build a separate controlled submission flow with durable attempts and safe recovery from ambiguous outcomes.
4. Independently verify the exact transaction and payment operation from network evidence.
5. Generate privacy-aware receipts only for payments that have actually been verified.

We will demonstrate a funded Testnet transaction and its verifiable hash before claiming end-to-end payment execution. Test assets have no monetary value.

## Longer-term: stablecoins, developers and agents

- Supported Stellar stablecoin payment requests, asset/trustline safety, merchant flows and reconciliation.
- Developer APIs, typed client examples, access control, idempotency and signed status notifications.
- Permission-limited agent/MCP capabilities, with human approval and spending policies for financial actions.
- Potential fee-sponsorship and Stellar smart-wallet integrations after technical/security validation.
- Exploration of regulated provider-backed off-ramps and broader ecosystem partnerships; **not available today**.

We will revise these priorities based on security requirements, ecosystem feedback, contributor capacity, and proof that the previous milestone works. There are no announced release dates.
